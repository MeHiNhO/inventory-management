Catalyst Components architecture

A read-only inventory dashboard. A Vue 3 single-page app calls a FastAPI service, which filters JSON data held in memory. There is no database, no real login, and no write path.

Vue 3 + ViteFrontend on port 3000
FastAPI14 GET routes on port 8001
7 JSON filesLoaded once into memory
40 tests passBackend only, none for the UI

System architecture

Three layers, with the browser as the only client. The whole API is one file, server/main.py. Much of the business maths, such as the Overview charts and Finance totals, runs in the browser as computed values.

Where the code and its docs disagree

Found by reading the source, running the app and checking the data. These are the places most likely to surprise someone new.

  • Most Overview KPIs are fixed numbers. Inventory turnover (4.2), orders fulfilled (187), fill rate (96.8%) and processing time (2.8 days) are constants in Dashboard.vue. Only revenue comes from the API, so the other four ignore every filter.
  • The frontend calls routes that don't exist. Six of the 17 methods in api.js have no backend route: four for /api/tasks and two for /api/purchase-orders. Loading tasks returns 404 on every page load.
  • Purchase orders are half built. The Pydantic models and an empty purchase_orders.json exist, but there are no routes, and Dashboard.vue:289 uses a PurchaseOrderModal component that doesn't exist.
  • Demand forecasts barely overlap with inventory. 8 of the 9 forecast SKUs aren't in inventory.json. The Demand page filters by matching those SKUs, so any Location or Category filter can show one forecast at most.
  • Backlog.vue can't be reached. The view exists, but no route or nav link points to it. Backlog data only appears on the Overview page.
  • Reports.vue stands apart. It uses the Options API, calls hardcoded URLs through axios instead of api.js, ignores the filters, has no translations and logs heavily to the console.
  • The project docs overstate or miss things. CLAUDE.md says four filters apply to all data, which the table above disproves, and it doesn't list the /api/reports routes. tests/README.md lists a test_orders.py that isn't in the repo.
  • Text is garbled on Windows. mock_data.py:17 opens JSON without encoding="utf-8", so ± arrives as Â±.
  • Security is demo-grade by design. useAuth is a hardcoded mock user, CORS allows all origins with credentials enabled, and main.py binds to 0.0.0.0. It should stay on a trusted local machine.
